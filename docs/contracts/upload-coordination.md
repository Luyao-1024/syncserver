# 上行租约、进度门槛与 dirty 回调契约 v1

日期：2026-10-13。状态：根据用户最新规则冻结设计，尚未实现。M2 现有 CRUD、事务和幂等能力保持已验证状态；本契约的接口/字段/行为需 M3、M4、C1 分别实现，不能视为已开放的 API。

## 规则入口

1. 同一 namespace（同账户同步库，覆盖其全部 zone）同时只有一个有效设备上行租约；下行可多端并发。
2. 客户端正常同步先下行；上行前获取租约，持锁检查云端最新 token 与本地 token 的同步进度。
3. 已追平则上行；未追平则继续持锁重新下行、完成本轮范围的资源/冲突协调，再检查；持锁期间独立保活。
4. 上行按删除 → 修改 → 新增执行。修改区分元数据与内容，元数据修改不上传文件。
5. 获取租约失败直接跳过本轮上行；不在本轮重试抢锁，不清 dirty，不扩大上传范围。
6. 租约到期/续租明确失效时立即中止当前和后续未完成上行任务，并逐项报错；迟到成功回调不能恢复这轮任务。
7. dirty 直接是本地数据库记录的字段，不另写 dirty 文件、另建 dirty 镜像表或持久化另一份 dirty 队列；上行成功确认回调才更新对应 dirty/上行确认基线字段。

## 同步流程

```text
正常下行，完整接收固定水位清单/变化并处理本轮冲突
  → 获取上行租约一次
      → 失败：本轮上行 Skipped，dirty 保持，正常下行结果保留
      → 成功：启动保活，持锁进行进度检查
          → 未追平：持锁重新下行（并发读取仍允许）→ 再检查
          → 追平且本地协调已完成：冻结本轮数据库任务视图
              → 删除 → 修改（元数据/内容）→ 新增
              → 每项有效成功确认回调更新对应数据库字段
              → 所有任务结算，释放租约
```

任何租约失效会使该轮进入不可逆的 Aborted；停止新任务、取消正在发送的正文和关联准备工作，并使所有未完成上行任务 Failed(UPLOAD_LEASE_LOST)。独立的正常下行任务不被连带终止。下次同步重新走下行/获取租约流程，不在已失效轮次内重新抢锁继续剩余任务。

## token 判定与本地就绪

比较的是同 namespace、同 zone、同 database_generation、同 kind 的有效 zone syncToken。客户端不通过不透明字符串是否相同推断最新；服务端验证签名/范围/种类/代际/分页状态后，在持锁的数据库事务中捕获已提交水位 H，返回语义判定和云端最新 token。

本地有两个接收进度字段（均为既有同步数据库中的字段，不是 dirty 台账）：

- ingestToken：可靠保存了哪些元数据页与待办；允许资源下载尚未完成。
- appliedToken：完整固定水位投影已协调、该轮明确下载范围内的双资源/本地发布和冲突已处理。上行门槛使用它，而非仅使用 ingestToken。

进度检查覆盖租约固定的本轮目标 zone 集合（非空，每次获取最多 20 个）；所有实际写入必须在这个集合中。原有上传/下载范围仍由客户端配置控制，持锁不授权扩大到未选择的照片。database token 仅证明 zone 变化发现进度，不能代替各目标 zone 的记录下行；snapshotToken/query marker/未结束分页 token 都不能作为已追平证据。

给定本地完成位置 P，服务端检查各目标 zone 在 `P < seq <= H` 是否仍有未接收变化。无相关变化时，其他 zone 写入造成 namespace 水位上升或 token 编码不同，都不阻止本 zone 被判定为当前；返回可规范化到 H 的最新 zone token，避免反复拉取空变化永远不相等。P 超过 H/代际变化是 EXPIRED_SYNC_TOKEN，签名/范围/种类错误是 BAD_REQUEST，SQL 故障不能伪装成过期。

客户端还检查本地 inbox/投影/明确范围内待办和冲突是否完成；服务端无法证明客户端磁盘实际已就绪。进度接口的 localReady 是客户端声明，不能用它替代客户端自己的数据库/发布屏障检查。appliedToken 在完成这些步骤后才推进；仅拿到服务端最新 token 不得提前推进它或清 dirty。

锁内重新下行时，租约继续保活；资源失败则不进入上行，结算失败并释放租约，dirty 保持。不能退回先释放锁、下行、未检查就上行的竞态流程。

首次进度检查通过后，记录本轮的 verifiedHead，冻结任务再进入删除阶段。自己的写入会产生新云端 token，但不会撤销这次门槛；不要求每项写入后重新下行追自己的变化。上行回调不直接将本地接收 token 设置为最新云端 token；下一轮正常下行可靠接收这些变化。

## 租约与 fencing

默认租约 90 秒，推荐客户端每 30 秒保活；这是新的待实现配置，不是 M2 已生效参数。持锁重新下行、缩略图生成及大文件传输期间持续保活。保活使用独立异步任务和控制请求配额，不排在长传输或普通数据库请求洪峰之后。续租不重置上传正文的空闲/总时长限制，不使过期上传 URL 获得新请求权限。

服务器持久维护 namespace 的单调 fencing counter，每次授予新租约递增；令牌绑定 namespace、database_generation、leaseId、deviceId、租约代次及固定 zone 集合。设备 ID 不是持锁凭证，持锁 token 必须保密。leaseToken 稳定地证明租约身份，有效性以服务器当前期限/代次为准；续租不让正在接收的长请求因旧凭证固定到期而失败。已过期的租约不能续租复活，即使暂无新持有者也必须重新获取新代次。

正常运行由服务器单调计时判定过期，客户端时间不参与判断。服务器重启先使旧租约失效并推进持久租约代次；这与 database_generation 分离，普通重启仍不使元数据同步 token 失效。

所有用户变更入口（records/modify、上传预留/续期/正文接收/成功确认、照片绑定、将来的导入入口）必须统一校验；不能让旧 M2 路径或兼容别名绕过。租约与阶段在请求接收时及数据库最终提交时检查，长流还监听失效取消信号。所有版本条件和成功 receipt 仍与记录提交同事务。下载/lookup/query/变化/会话与幂等状态读取不要求上行租约。

文件稳定发布不与 SQLite 同事务：失效后停止旧请求授权，已持久发布意图只做安全结算/隔离，不为旧租约产生新的记录绑定或新成功确认。正式不可变对象不因取消删除；未确认对象留在受控待恢复状态。已经在有效租约下提交的事务不回滚。

## 原生接口（待实现）

所有接口仍用本服务 Bearer。租约接口与进度判断不读取资产正文、不计算既有资产 hash，也不产生媒体 changes。

| 路径 | 方法 | 语义 |
|---|---|---|
| `/v1/upload-leases` | POST | 一次获取；deviceId + zoneIDs，返回 leaseId/leaseToken/fencingToken/期限 |
| `/v1/upload-leases/{leaseId}/renew` | POST | 有效持有者续租；过期不复活 |
| `/v1/upload-leases/{leaseId}/check` | POST | zoneTokens + localReady，锁内返回云端最新 token 与 isCurrent/mayUpload |
| `/v1/upload-leases/{leaseId}/phase` | POST | 通过门槛后 Delete → Modify → Create，只能前进且等待已发出写入结算 |
| `/v1/upload-leases/{leaseId}/release` | POST | 只释放当前匹配租约，迟到释放不能释放新持有者 |
| `/v1/operations/{operationId}` | GET | 无须租约读取已提交结果或 Pending 子项，用于响应丢失/失锁恢复；不存在返回 UNKNOWN_ITEM |

fencingToken 使用十进制字符串避免 JSON 客户端整数精度丢失。变更与租约控制请求带 `X-Sync-Lease-ID`、`X-Sync-Lease-Token`、`X-Sync-Lease-Fence`；同名重复头拒绝，path leaseId 与头不一致拒绝。签名 URL 的上传能力另绑定 leaseId/fence/上传意图；其较长有效期不能绕过较短租约。

获取不到租约返回 409 UPLOAD_LOCK_BUSY；进度尚未追平时 check 返回正常状态 isCurrent=false；尚未通过门槛的变更返回 409 SYNC_NOT_CURRENT；阶段不符返回 409 UPLOAD_PHASE_MISMATCH；过期/旧代次/明确失去租约返回 409 UPLOAD_LEASE_LOST。认证、输入错误和内部故障仍保留原错误类别。客户端任何获取失败都停止本轮上行并保留原因；如果响应丢失但服务器已授予，未收到凭证的客户端不能上传，服务器靠超时回收。

Acquire 请求示例：

```json
{"deviceId":"example-device-a","zoneIDs":[{"zoneName":"PrimarySync"}]}
```

Check 请求/响应示例（所有 token 均为占位符）：

```json
{"zoneTokens":[{"zoneID":{"zoneName":"PrimarySync"},"syncToken":"local-applied-zone-token"}],"localReady":true}
```

```json
{"isCurrent":false,"mayUpload":false,"zoneTokens":[{"zoneID":{"zoneName":"PrimarySync","ownerRecordName":"_defaultOwner"},"syncToken":"cloud-latest-zone-token"}]}
```

## 删除 → 修改 → 新增

普通元数据与照片操作都按这个阶段顺序；同一阶段内可以有界并行，同一照片的操作串行合并。phase 前进前必须确认该阶段已发出的任务结算。请求批次在单阶段内使用相同 operationType；照片对依然是同 zone atomic 两项 delete/update/create，不允许用旧的混合类型批次穿过协调阶段。M2 历史接口支持混合批次的事实保持可追溯，启用协调契约后的新行为需明确测试，不能静默保留绕过口。

- Delete：明确云端删除意图，保留本地待删数据库记录直到成功确认，不上传文件。取消仅本地副本/退出上传范围/磁盘离线不自动等同云端删除。
- Modify：元数据只改字段、复用原图/缩略图；内容变更上传变化的资源并生成对应缩略图，原子更新同一照片两条记录与 generation。元数据和内容同时 dirty 合并为一次照片更新。EXIF 编辑若改变实际原图字节属于内容修改。
- Create：两个资源稳定 Published 后原子创建照片记录对；已退休名称不能复用。

先删除释放待删路径，重命名互换等修改内依赖仍用 atomic 最终图/路径校验。不能因为顺序改变放宽版本条件。依赖的删除失败，后续关联操作保持失败/待办，不覆盖冲突路径；独立操作可继续。未选定的上传对象不因 lease/dirty 被加入本轮。

## dirty 是数据库字段

C1 在本地既有同步记录中增加/使用 dirty 字段，不为 dirty 建立独立文件、表或持久化队列。任务队列只是当前字段的派生执行视图。已有远端投影、下载待办、配对发布台账和 HTTP operationId 的恢复信息继续各自承担职责，不保存第二份 dirty 真值。

| 字段状态 | 处理 |
|---|---|
| CLEAN | 不安排上行 |
| NEW | 新增；可以同时记后续 META/CONTENT 位，分类仍是新增 |
| METADATA | 元数据修改 |
| CONTENT | 内容/资源组合修改 |
| METADATA + CONTENT | 合并照片更新 |
| DELETE | 待删；保留 DB 记录及身份/版本/删除时间，优先删除分类 |

本地真实新增/编辑/删除更新这个字段及相应 localRevision/edit time；入队、获取租约、发送请求、写暂存或单资源完成都不清字段。上行读取数据库冻结本轮任务视图，上传期间新变更仍写回同一数据库字段，下一轮处理。

成功回调带 namespace/job/config/cycle 关联、operationId、任务捕获的本地版本和服务端已确认结果；同一客户端事务登记可信基线并仅清除已完成的对应变更。若本地又修改，不清新 dirty。成功创建后即使有新修改也应登记云端身份，剩余 dirty 转为修改/删除义务，避免下一轮重复 create。已发送创建后用户删除而结果不确定，先查清既有提交，不能因看到 NEW 就假定云端不存在。

失败、跳过、失锁和失效/过时回调均不清 dirty。判断 token 已追平本身也不清。已确认完成的前项不因后来失锁回滚；“全部报错”覆盖当时正在执行/尚未启动的上行项，不改写已经有效确认的成功事实。

上行成功是已确认的语义完成，不仅是 HTTP 200：原子批次所有项成功或 nonatomic 对应项成功，并完成本地结算；下行令目标状态已与云端一致时可以执行 AlreadyCurrent 的只读成功确认回调，不为清 dirty 制造一次空写。它同样要求有效轮次/本地版本校验，禁止用 token 相等或未验证的目标状态假装成功。

下行 LocalReady 事务仍按既有发布契约保存下载基线/待办/token，不代表上行成功，不直接清待上行 dirty。

## 冲突与回环

本地 dirty 不等于双方都变更；先根据记录/内容基线判断远端是否变过。云端未变则保留本地上行义务；双方同一内容/字段都变更时按更新事件时间选择较新版本。本地元数据与远端内容的独立变更可以合并。不同 photoId 的同路径对象按路径冲突处理。

区分 metadataModifiedAt、contentModifiedAt、deletedAt（UTC 毫秒），不要用照片拍摄时间或上传完成时间代替编辑时间。同时间以稳定 deviceId/deviceChangeSeq 决胜；设备偏时仍有歧义，保留内容冲突输方副本。服务端未来保留变更事件信息和删除时间，当前 M2 墓碑尚无这些字段，不能假装现有记录已可按删除时间仲裁。

远端胜出先完成冲突副本、双资源校验/本地发布和基线协调，然后通过有效成功确认路径处理对应旧 dirty；下行不得未经决策覆盖正在编辑的新本地版本。扫描/监视器辨别同步内部发布，不能把下行写入再标成新的本地修改。只删除本地副本/范围退出的抑制仍有效。

## 失锁与失败矩阵

| 事件 | 当前/后续上行 | dirty / 已有成功 |
|---|---|---|
| 获取失败（busy、认证、网络、响应不确定） | 本轮全部 Skipped；不在本轮抢锁重试 | 字段保持；正常下行结果保留 |
| 锁内 token 落后 | 不启动写入，持锁重新下行并保活 | 保持 |
| 租约有效且资源/协调就绪 | 顺序执行冻结任务 | 有效成功回调按版本更新 |
| 明确失锁或本地保守到期 | 当前流取消、所有未完成项 Failed(UPLOAD_LEASE_LOST) | 未完成项保持；前项已确认成功保持 |
| 失锁后迟到 HTTP 200 | 忽略对已终止轮次的成功通知 | 不清；下一轮读取提交事实恢复 |
| 失锁前已经提交但响应丢失 | 本轮仍报错，不能承诺服务器未写入 | 保持；新轮读取 receipt/状态后走成功确认或重新协调 |
| 单项业务/资源失败，租约仍有效 | 关联后项暂缓，独立项可按阶段继续 | 失败项保持，成功项回调正常 |

续租网络超时不自动延长本地授权；只有已收到的服务器期限有效。可在已知安全期限内有界重试控制请求，达到保守截止时间或收到 UPLOAD_LEASE_LOST 即终止。大文件保活不等于断点续传或取消所有资源时限，首版网络中断仍按会话状态重传。

## 实施与验收

见[实施计划](../design/implementation-plan.md)、[验证计划](../design/verification.md)和 [ADR 0004](../adr/0004-upload-lease-and-database-dirty.md)。核心验收是：两个设备竞争只能一个持有、持锁补拉无竞态、失锁逐项失败且无迟到清 dirty、callback 与新本地修改竞争不漏传、阶段顺序和下行并发不互相阻塞。
