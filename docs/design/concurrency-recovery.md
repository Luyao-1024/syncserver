# 条件写入、事务和恢复

状态：M1 已实现迁移、范围检查、启动登记和有界单写入者；下述记录事务/资产恢复待 M2/M4。SQLite 事务和文件发布必须通过持久意图衔接。

## 条件命令

create 要求不存在；update/delete 要求 recordChangeTag 等于当前 revision。检查与写入同事务。成功时更新 records、追加 record_versions/changes，并保存 operation receipt。

同一对象的并发条件请求最多一个成功。后续冲突响应提供当时服务器的 revision，客户端重新规划；服务端不自动合并客户端业务字段。

CPLAsset/CPLMaster 采用[一对一最终图规则](../contracts/photo-records.md)：成对创建/内容更新/删除，非 atomic 拆对拒绝，metadata-only 单项更新可行。退休名称不复用。

v0.1 禁止 forceUpdate/forceDelete 绕过条件。atomic 批次限单 zone，任一错误回滚所有操作；非 atomic 按顺序逐项提交并返回逐项结果。

## 幂等

客户端可提供 HTTP Idempotency-Key，映射为本服务 operation_id。scope + operation_id 唯一，绑定规范化请求指纹；重复请求返回原提交域结果，重渲染短期 URL/receipt，不生成第二条变化。ASSETID 先核验数据库与证据，再归一化为稳定资产引用；请求指纹排除已验证的临时 URL/receipt，防止凭证刷新导致假冲突。键相同内容不同必须拒绝。非 atomic 批次由批次键和索引派生逐项键，部分成功后重试保留已提交结果，不重新执行成功项。

不带 operation_id 的 CloudKit 风格请求仍遵守版本条件，但响应丢失后不保证返回与第一次相同的结果。客户端需读取记录核对，不能无限重复 create。

## 发布顺序

1. 完成输入校验并 fsync 暂存文件。
2. 提交 PublishPrepared 意图，包括 namespace、暂存身份、摘要、大小和目标对象身份。
3. 将文件不覆盖地原子发布，fsync 对象目录。
4. 事务提交 assets Published、会话完成和 receipt；记录引用必须在此后。
5. 结算意图和暂存清理；清理失败可重试，不回退已提交成功证据。

不能在数据库事务内等待上传或执行全文哈希。不能在步骤 3 前返回 Published。

## 故障矩阵

| 中断位置 | 重启处理 |
|---|---|
| 接收中，没有发布意图 | 保留/回收未完成会话；v0.1 重新上传，不假装支持续传 |
| 暂存稳定，意图未提交 | 未登记的暂存按受控规则清理，不成为资产 |
| 意图已提交，文件未发布 | 核对暂存身份、大小；仅恢复该意图的发布 |
| 文件已发布，数据库未确认 | 核对意图、对象与摘要证据，完成资产事务 |
| assets 已确认，响应未送达 | 通过 receipt/session status 返回既有成功 |
| 记录事务中进程退出 | WAL 回滚或恢复整体事务，不留半条变化 |
| 清理暂存失败 | 保留失败原因，延后重试，不删除正式对象 |

恢复期间允许核验意图涉及的文件；不得因此每次启动重新哈希所有资产。遇到缺失对象、身份不一致或目录外路径，进入显式损坏状态，不通过静默清理掩盖数据问题。

## 启动与关闭

启动先验证数据目录和配置、迁移 schema、恢复意图，再开放 ready 状态。恢复失败不对客户端声明 ready。健康检查只表示进程存活。

关闭先停止新写入，等待已进入安全结算阶段的任务完成；未结算操作保留持久证据。后台任务必须有有界队列和取消点，不能取消正在提交的事务后仍返回成功。

## 外部写入

受管理对象目录只允许服务端写入。直接编辑/删除对象不属于支持路径；后续外部导入器必须先稳定观察内容，再通过正式发布和记录接口入库。未受控的外部写入不能靠 mtime 缓存承诺强一致。

## M1 启动框架

`service_starts` 在独立事务中记录 Recovering，然后在完成元数据 quick_check/外键检查后进入 Ready。重启将旧 Recovering/Ready 登记为 Interrupted；正常关闭排空数据库命令，写入 Stopped 并执行 WAL checkpoint。只有初始化完成才建立可就绪的应用状态，启动失败不会开放 HTTP 监听。

同目录锁由数据库线程持有至连接关闭。命令队列满直接返回 SERVER_BUSY，不创建无界等待发送者。请求取消不会撤销已经接受的数据库命令；关闭原子停止提交，再执行已接受命令并等待线程退出。并发 shutdown 调用等待同一次排空完成。

M1 没有 upload_sessions、publish_intents 或 Published 资产；恢复仅检查元数据，不读取 objects/staging 的内容。实际发布窗口恢复将在 M4 实现，不能用启动登记测试替代。
