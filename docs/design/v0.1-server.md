# 基本服务端实现与验收

日期：2026-10-14。M3-A/B/C、M4 基本实现和 M5 的 CI/部署工具已进入代码；具体运行/推送/远端 CI 证据以提交的 Tests 与本次交付说明为准。当前能力 stage=M4，表示资源已开放；不表示公网已经部署或 PhotoViewer/C1 已接入。

首次正式发布前，不将开发版数据库迁移兼容作为交付要求。现有迁移文件仍可执行，但没有稳定的旧开发版数据库支持承诺。当前结构的事务、持久化、恢复、generation 与普通重启的 token 连续性仍是必须验证的正确性。

## 已开放接口

CloudKit 基址：`/database/1/{container}/production/private`。Bearer 与配置固定 namespace，接受 JSON/text/plain，拒绝重复 JSON key、未知语义参数和跨范围访问。

| 路径 | 已实现能力 |
|---|---|
| `/zones/list` | 配置的固定 zone 集合 |
| `/records/modify` | 单阶段 create/update/delete，revision、atomic/nonatomic、幂等与最终提交 lease/fence 校验 |
| `/records/lookup` | 当前读取；提供 snapshotToken 时读取历史固定 H，快照不可跨 zone |
| `/records/query` | recordType、desiredKeys、recordName 升序 keyset、固定 H、共享 snapshotToken |
| `/changes/database` | 固定 H 的变化序号分页、本页 zone 去重；初次返回全部 zone |
| `/changes/zone` | zones 数组、逐 zone 错误、完整不可变版本、墓碑、固定 H 与 moreComing |
| `/records/changes`、`/zones/changes` | 与 changes/zone 完全相同的请求/领域逻辑 |
| `/internal/records/query/batch` | `batch` 数组最多 20 个 query 请求；同事务捕获 H，逐项结果；不支持私有计数索引 |
| `/assets/upload` | lease/intent 绑定、最多 200 个资源预留、持久幂等 |

原生 `/v1/`：snapshots；upload-leases 获取/renew/check/phase/release；operations 无锁状态读取；uploads 状态/renew/content；assets 描述及 GET/HEAD content。健康、就绪和 capabilities 保持已有入口。

`clientId`（有界字符串）、`remapEnums`（布尔）是 CloudKit 顶层已记录的非语义提示。`getCurrentSyncToken` 在 query 中识别，响应始终保留 token。zone 的 desiredRecordTypes 仅为提示，不过滤事件；因此类型扩展不会跳过历史。排序仅固定 recordName 升序；非空 filterBy/sortBy 明确 501。

## token、快照与接收

签名以种类域分离；验证签名、版本、namespace、zone、generation、位置和固定 H。正常重启维持有效的元数据 token；错范围/错类/坏签名 BAD_REQUEST，恢复代际/未来水位 EXPIRED_SYNC_TOKEN，SQL 故障 INTERNAL_ERROR。

快照不设时间到期，保留全部历史。query 从每个名称最后 `seq <= H` 的版本过滤墓碑/recordType；不使用 OFFSET 或当前投影替换旧字段。页数上限 200，同时按完整 wire（含资源 URL/receipt）的字节预算缩短页。desiredKeys 最多 256 个标识、JSON 编码最多 8 KiB，以保证 marker 的有界签名封装。query marker 绑定 recordType/desiredKeys/末名称；marker 与 snapshot 同时存在必须同 H。

zone/database 增量保留本轮固定 H，末页才成为完成位置。atomic 批次允许跨页，接收方不能把半页照片对发布。其他 zone 的全局水位变化可通过一次空增量规范化；上行 check 按相关 zone 的变化索引比较，无须原始 token 字符串相同。自己的有效上行不撤销本轮已通过的门槛，不乐观推进客户端接收 token。

[接收示例](../../examples/receive_metadata.rs)与[示例持久层](../../examples/support/receiver.rs)演示 inbox/ingest 同事务、最终 H 投影及双资源待办；pending 未完成时不推进 applied。真实 HTTP 测试包含接收事务故障、半页对、重启、两资源实际下载和最后进度。这是合成接收器，不是 PhotoViewer 数据库、dirty 回调、缓存或 UI 的实现。

## 上行协调

namespace 只有一位有效上传持有者。TTL 默认 90 秒、heartbeat 建议 30 秒；固定非空目标 zones 最多 20 个。新租约递增持久 fence，正常重启使旧租约失效并递增 fence，不改变同步 generation。有效期由服务端单调时钟判断，客户端时间不参与。

控制 HTTP 配额及数据库控制队列独立有界并优先处理；长文件 I/O、hash、缩略图解析在阻塞任务上运行，不占用 SQLite 事务。普通读取不获取上行锁。check 必须提供完整完成态的 zone token，加本地 localReady；客户端仍须自己证明资源/冲突完成，服务器无法验证客户端磁盘。

check 通过后进入 delete；phase 仅 delete→modify→create，拒绝混合类型批次、逆向/越级及仍有正在接收/发布的会话。每项写入 admission 与最终提交都检查租约。签名身份 token 不因 renew 改变；超时不能复活。失锁的长流及时终止，后续同凭证任务失败；先前已提交事实仍可无锁读取，不能倒退。

## 事件时间扩展

记录输入/输出 `_syncserver` 含可选 metadataEvent、contentEvent、deletionEvent。每个事件是 `editedAtMs`（非负 UTC Unix 毫秒）、`source`、`eventId`。客户端可提供真实编辑事件；缺省的新变化由服务端提交时间和 revision 建立 server 来源事件。正常独立编辑保留其他类别旧事件；墓碑保留删除与旧事件。未知的旧历史时间保持缺失。

照片内容变化按 generation/两角色/masterRef 等实际差异区分；收藏、标题、路径等不生成新内容事件。上传时间、EXIF capture time 和文件 mtime 不能替代此模型。客户端冲突合并及 losing copy 仍属于 C1。

## 资源传输与安全发布

原图/缩略图是独立资源；原图 opaque，缩略图完整有界解码 JPEG/PNG、长边不超过 2048、最多 2 MiB。上传输入通过有界 64 KiB 队列流式写暂存，同遍计算 SHA-256/长度并核对预留。原图/缩略图各保留传输配额；配置为 1 时每角色仍有 1 个配额，以保证角色隔离，实际最大总配额为 2。

会话有效 24 小时，上传/下载 URL 有效 15 分钟。POST content 需要签名上传 URL 和三个 lease 请求头；Bearer 不替代上传 capability。Reserved 可 renew，Receiving/PublishPrepared 拒绝竞争，Published 不接受重复正文。普通网络中断创建新会话，不支持上传续传。

持久状态：Reserved→Receiving→PublishPrepared→Published，失败进入 Failed/Expired。Verified 和 ObjectPublished 是流水线边界，不单独作为已成功 DB 状态。暂存 fsync 后持久写发布意图；同文件系统 hard-link 排他发布、不覆盖已存在对象，unlink 暂存、fsync 对象及两目录，最后在有效 fence 下确认资产与会话。只有 Published 资产可被照片绑定。

元数据轮询/HEAD 不读正文也不 hash。GET 流式读对象，支持单 Range、If-Range、If-Match、If-None-Match；强 ETag 来自持久 SHA-256。缩略图不能回退到原图。描述与签名能力绑定资源/角色/方法/期限/范围。

输入 ASSETID 核对 receipt、资产行、摘要/长度与角色资格，然后去除临时 URL/receipt，持久化稳定身份；逻辑幂等指纹同样不受凭证刷新影响。读取/旧成功 receipt 重新生成短期描述，不生成新 revision/change。同 digest/size 去重；后续 thumbnail 验证可补齐同一对象的验证属性。读取只刷新 URL/receipt，不改变旧版本的 MIME/尺寸；逻辑资源指纹只包含稳定资产身份，后续资格补全不使旧请求冲突。nonatomic 子操作使用 savepoint，领域失败不提交绑定删除等中间变化；写入前预算包含 wire 扩展，渲染过程也有总字节上限。

同内容并发发布仅串行短暂的 hard-link/unlink 窗口，流式传输与 hash 仍按角色并行。重启只扫描待恢复意图/会话记录；先处理所有相关暂存链接，再按摘要对待恢复对象校验一次，避免重复意图/已失败意图留下的临时第二个链接造成误判。接收中旧会话失败并清暂存；已有意图安全完成对象持久化、校验该对象后隔离，不给旧 fence 新成功；已提交对象保持 Published。不扫描/rehash 全部既有图库，不做资产 GC。周期任务仅使过期 Reserved 会话失效，不动正文。

## 2026-10-16：日志落库与留存

日志进入独立管道：单一 `tracing` subscriber 渲染标准输出并把同一记录写入私有数据目录的 `logs.sqlite`，控制台与库内容共用一次脱敏，不可能出现两种字段可见性。等级由 `SYNC_LOG_LEVEL`（默认 info）与 `SYNC_LOG_PERSIST_LEVEL`（默认继承前者，`off` 时完全不建库）配置；`SYNC_LOG_PAYLOAD=on` 且等级含 debug 时才渲染记录名/路径/标题等库内容字段，凭据类字段任何配置下都脱敏。

未压缩窗口由 `SYNC_LOG_RETENTION_RAW_SECS`（默认 86400）决定，窗口内日志按契约原样保留、不设条数或字节上限；超窗记录压缩为 gzip NDJSON 段并在同一事务中删除原行，压缩总量受 `SYNC_LOG_ARCHIVE_MAX_BYTES`（默认 1 GiB）约束，超限按最旧整段裁剪并留 `warn`。落库队列为有界 `sync_channel`，满时丢最新记录并计数，不阻塞请求线程；`/v1/metrics` 的 `metrics.logging` 暴露深度、丢弃、写库失败、窗口行数与归档段/字节等增量计数。

等级策略覆盖请求、租约、资源发布、记录写入、会话与恢复：轮询/续租/状态查询为 debug，状态跃迁为 info，失锁与摘要不符为 warn，写库失败为 error。读取入口是只读的 `syncserver logs`，可在服务运行时执行。契约、脱敏清单与验收 L01–L08 见[日志与留存契约](../contracts/logging.md)，实现约束见 [src/logging/AGENTS.md](../../src/logging/AGENTS.md)。


## 2026-10-17：每用户 20 GB 配额

新增 `SYNC_USER_STORAGE_QUOTA_BYTES`，默认 20000000000 字节，每用户独立计算全部 zone 当前文件引用资源的逻辑大小及有效逻辑增长预留。相同对象被不同文件引用时分别计量；上传申请检查预留，记录创建/复制/更新以最终逻辑占用在事务内检查，超额返回 409 `STORAGE_QUOTA_EXCEEDED` 并回滚相应事务。去重对象发布仅结束传输预留，不直接增加用户已用空间。无需修改 schema 或同步 generation。`GET /v1/storage` 经现有认证读取当前账户空间，不需要租约、不读取资源正文；能力声明新增 storageQuota 和实际配置上限。

当前文件的原图/缩略图均计入逻辑占用；历史和未引用对象、数据库/日志/暂存和隔离对象不计入。删除释放逻辑配额，历史物理对象仍保留。完整边界见[配额契约](../contracts/storage-quota.md)，运行证据见[验证记录](verification.md)。本地实现不代表已提交、推送或部署。


## 2026-10-17：空间占用按媒体分类

`GET /v1/storage` 增加 imageBytes/videoBytes/otherBytes，`capabilities.storageUsageByMediaType=true` 表示支持。当前文件原始资源和缩略图大小合并归入所属文件类别，共享对象按每份逻辑引用计量，不单列缩略图。分类使用服务端原始资源 MIME，未知时按当前虚拟路径扩展名判断；未知归 otherBytes，三类之和等于 usedBytes。查询只读同一账户、同一事务下的元数据，既有配额与物理去重规则不变。契约见[空间查询](../contracts/storage-quota.md)，验证证据另列。
