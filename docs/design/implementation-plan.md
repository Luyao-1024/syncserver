## 设计冻结入口

[共享快照](../contracts/snapshots.md)、[照片字段](../contracts/photo-records.md)、[资源](../contracts/assets.md)、[客户端发布](client-publication.md)、[上行协调](../contracts/upload-coordination.md)和 [ADR 0004](../adr/0004-upload-lease-and-database-dirty.md)是开发入口。新的有效规则是持锁检查，落后持锁重新下行；获取失败跳过；失锁全部未完成项报错；删除→修改→新增；dirty 仅为本地 DB 字段，有效成功确认回调才更新。

## 依赖顺序

M1 → M2 → M3-A → M3-B → M3-C。先有已验证的 token/变化与本地投影模型，再实现可证明的“已追平”门槛；不能先开放仅凭客户端布尔声明的假 gate。M3-B 对 metadata 入口强制租约/阶段，已有 M2 无锁/混合类型请求将受新规则约束，需用租约-aware fixture 更新测试，禁止 legacy 绕过。

M4 的 I/O 可在相关边界稳定后准备，公开上行必须同时依赖 M3 的真实租约/gate 和 M2 的记录/照片验证。M5 依赖基础接口与恢复验收。C1 按客户端仓库自己的规则执行，不与服务端开发混合。

## 每阶段工作方式

1. 读模块 AGENTS 与冻结契约，先用聚焦测试验证失败路径和竞态。
2. 实现最小可验证功能；未完成 endpoint/capability 明确为未支持。
3. 契约改变同步更新矩阵、数据模型、状态机、验收和 README。
4. 推送 Rust 前执行最终代码树 fmt/clippy/build/test，提交 Tests 只列实际结果。
5. 文档提交只做链接/JSON/fixture/差异检查；部署、CI、C1 另记真实证据。

## 暂缓项

多账户、分享 ACL、推送/SSE、上传续传、块级差异、历史裁剪、资产 GC、S3、分布式数据库和 Apple 私有索引均需独立规格。缩略图先显示、原图懒下载和访问优先级仍暂缓。保活只避免租约在正常长传输中过期，不新增上传续传或取消正文限额。

## PhotoViewer 接入

在本地既有同步记录中用 dirty 字段及本地版本/基线关联，不另存 dirty 文件/表/持久队列；保留远端投影/下载待办和配对发布恢复台账的不同职责。先下行后取锁，锁内 token 检查和必要补拉，按阶段读取 DB 派生任务；本地用户仍可编辑，新变更下一轮处理。只在有效成功确认回调更新字段，失败/跳过/失锁不清。保持上传/下载范围、删除抑制、配置 generation，以及完整原图/缩略图后入库的已定 UX。
