# 实施计划与阶段门槛

状态：M0 文档基线与 M1 基础已建立；M2–M5 与 C1 待实现。M1 实现与验证见 [M1 基础](m1-foundation.md)。

| 阶段 | 交付 | 完成证据 |
|---|---|---|
| M0 | 需求、分层 AGENTS、架构、兼容、状态机与验收；独立 GitHub 仓库 | 文档链接/JSON/差异检查、推送 SHA |
| M1（已实现） | Cargo crate、配置、认证、能力声明、SQLite 迁移、启动恢复框架 | 实际 HTTP、范围固定、权限、队列、SIGKILL/SIGTERM 重启测试；见 M1 基础 |
| M2 | 记录 CRUD、revision 条件、历史、变化索引、operation receipt | 条件并发、atomic 回滚、查询计划 |
| M3 | 跨类型 snapshotToken、query/lookup 固定快照、database/zone token、inbox 分页、兼容 aliases/batch | 分页并发、墓碑、签名/范围 fixture |
| M4 | 上传会话、原图/缩略图角色、成对发布、流式摘要、恢复、HEAD/GET/Range | 去重、角色完整性、故障注入、正文零读取轮询 |
| M5 | CI、systemd/容器、部署 smoke、版本发布与客户端接入规范 | exact-SHA CI、实际服务验证 |
| C1（后续客户端） | 新 Provider、配对下载/发布、缩略图缓存导入；复用本地图库/详情 | PhotoViewer 实际入库门槛与宫格/点击验收，A15–A18 |

M1–M4 共同构成 v0.1 基本服务端。任一阶段未完成时 README 保留对应未实现项，不把局部 endpoint 当作服务端完整交付。

## 设计冻结入口

[共享快照](../contracts/snapshots.md)、[照片字段与生命周期](../contracts/photo-records.md)、[资源接口](../contracts/assets.md)、[客户端发布屏障](client-publication.md)已给出确定选择；开发阶段验证实现，不重新默默改变契约。

## 依赖顺序

M1 → M2 → M3；M4 的接收 I/O 可在 M2 边界稳定后开发，公开资产引用仍依赖 M2。M5 依赖基础接口和恢复都通过验收。

## 每阶段工作方式

1. 读取相应模块 AGENTS 和契约。
2. 用聚焦测试确定协议行为/失败路径，再实现最小可验证功能。
3. 同时更新兼容矩阵的状态，不增加未经测试的支持项。
4. 推送前执行当前阶段适用的完整闸门，提交说明包含 Tests。
5. 发布和接入另行记录实际证据；不操作 Apple 账户或原 WebDAV 生产服务。

## 暂缓项

多账户、分享 ACL、推送/SSE、上传续传、块级差异、历史裁剪、资产 GC、S3、分布式数据库和 Apple 私有组合索引均需独立规格与验收。缩略图先显示、原图懒下载、访问优先级和远端占位也暂缓，不在 C1 中隐式恢复。

后续引入历史裁剪时优先定义 token 下界与客户端重建，而不是先定时删除行。引入 GC 时优先定义全部历史/快照/下载引用，而不是仅看当前记录引用数。

## PhotoViewer 接入

服务端基础完成后，单独修改 PhotoViewer 的 Provider 和远端投影/待办存储。接入采用每张照片原图/缩略图均就绪后入库，保留真实本地 URI/path；增加同步配对门槛和缓存导入，不扩展远端占位模型或访问触发原图下载。保留其上传范围、删除抑制、三方冲突、配置 generation 和本地发布恢复；按该仓库自己的 AGENTS 与测试要求执行，不在本项目默认改动相邻仓库。
