# 原图与缩略图的渐进同步

状态：必须实施的产品约束，尚无服务端或客户端实现。来源：用户 2026-10-13 的追加要求。

## 产品流程

上传包含原图和缩略图。初次下行按“元数据 → 缩略图 → 原图”分层；元数据和缩略图构成可浏览状态，原图随后自动低优先后台下载，不要求用户逐张点击才下载。

用户浏览到的图片或点击进入的图片提前进入对应下载队列。宫格始终显示缩略图；进入详情先显示现有缩略图，原图后台就绪后切换。后台原图下载不能阻塞宫格或详情首次显示。

“初始下行完成”与“原图全部就绪”是不同状态，必须显示分别可验证的进度。不能用缩略图成功冒充原图同步成功。

## 服务端责任

- 每张逻辑照片关联 original 和 thumbnail 两个可信资源角色，独立 AssetId、digest、size、MIME 和像素尺寸。
- 两个角色绑定同一内容 generation。更新原图时缩略图必须对应新原图，不能留下旧预览。
- 资源描述通过记录元数据取得；查询元数据不下载任一正文。
- 下载入口根据角色只返回指定资源，不能把原图偷偷作为缩略图回退。
- 记录删除、修订和资源生命周期仍遵守事务/条件规则。

首版客户端生成缩略图并上传，服务端不承担全库原图转码。缩略图保持完整宽高比例、不放大、已应用方向，使用适合预览的色彩表示；宫格裁剪由 UI 实现，不裁掉详情所需内容。

v0.1 缩略图接受 JPEG 或 PNG；建议最长边 1024 像素，服务端限制最长边不超过 2048、大小不超过 2 MiB，并以有界解析验证类型和尺寸。客户端压缩质量可调；不能将用户原图重写成缩略图。视频/Live Photo 的完整复合模型暂不在首版，新增支持须单独定义 poster 与伴随资源。

## 记录绑定

通用 Record CRUD 仍支持非照片记录。照片领域有额外完整性约束：新建活跃逻辑照片必须同时绑定已发布且同 generation 的原图与缩略图。

CloudKit 风格表示采用 CPLMaster 保存资源描述（例如 resOriginalRes、resJPEGThumbRes），CPLAsset 保存可变图库属性与 masterRef。两者共同发布使用单 zone atomic 批次，不能只更新一半。上传上下文绑定 content generation，缩略图另声明 sourceOriginalSHA256；服务端核对它与实际原图摘要一致。首版不重新解码原图来证明视觉派生关系，客户端必须从同一稳定原图快照生成缩略图。字段布局为本服务定义的受支持子集，不声称完整 Apple CPL 模型。

对于非照片记录不强制两个角色。发布顺序可先上传缩略图再上传原图；只有两者和绑定事务完整后照片才进入活跃清单。未完成会话不冒充可同步照片。

元数据编辑可复用相同的两个资源；内容编辑生成新 original/thumbnail 对，并按期望 revision 原子更新。去重按资源实际字节进行，不能因为原图 digest 相同就忽略用户选择的预览版本。

## 客户端状态与目录

```text
MetadataOnly → ThumbnailQueued → ThumbnailReady → OriginalQueued → OriginalReady
                     ↘ ThumbnailFailed                ↘ OriginalFailed
```

可用性与队列状态分别存储，重试不丢失已有 thumbnail。记录存在、缩略图存在、原图存在不能用一个布尔“已下载”表示。

缩略图写专用缓存目录，原图通过 staging 校验后进入原图缓存/正式媒体位置；不会把缩略图塞进原图目录让扫描器误认为原件。原图路径在未下载时可空，图库项目通过稳定远端 ID 识别。

这要求后续 PhotoViewer 支持“有元数据/预览但没有原图”的项目，不能沿用“原图完全落盘才进入图库”的旧接入前提。本仓库定义协议与参考流程，不在文档阶段修改 PhotoViewer。

## 下行调度

正常流程先取得完整页/增量元数据并持久化待办，优先下载缩略图，再自动下载原图。对同一项目先尝试预览；全局不能因一个失败缩略图永久阻塞其他就绪项目的原图。

浏览/点击允许提前提升相关任务，不等待全库缩略图完成。优先级建议为：

| 优先级 | 任务 |
|---|---|
| P0 | 点击项尚缺的缩略图 |
| P1 | 当前打开图片的原图 |
| P2 | 宫格当前可见项的缩略图 |
| P3 | 用户正在浏览可见项的原图 |
| P4 | 相邻视口的缩略图预取 |
| P5 | 普通后台缩略图 |
| P6 | 普通后台原图补齐 |

可见项原图使用短暂稳定可见判定（初始建议 250 ms，可调）避免快速滚动立即启动全部原图；点击立即提升，无该等待。

队列以 namespace + AssetId + role/content generation 去重。在进行中的后台下载只调整优先级或复用结果，不能再次发起相同内容请求。缩略图和原图使用独立有界额度，初始建议 2 个缩略图槽和 1 个原图槽；以测试调整，不能让单个大原图占满全部请求槽。

退出页面会撤销高优先访问意图，但保留普通后台补齐意图。只取消尚未开始的预取，已接收字节按恢复规则结算。下载受全局同步开关、网络和用户范围控制；不因优先级提升扩大下载权限。原图补齐前检查客户端可用空间与缓存预算，不足时保留预览和原图待办并报告原因，不把预览就绪改成原图已完成。

## 详情页切换

原图校验和发布成功后，只有当前 PhotoId、内容 generation 和显示请求仍匹配时才替换详情图像。用户已切换图片时，结果只进入缓存，不回写旧页面。

缩略图和原图采用相同方向、宽高比例与视图状态，切换保留缩放/位置，不突然跳回初始视图。缩略图缺失时显示明确占位和进度；不得显示其他图片旧预览。

## 验收

- 常规首轮只先请求元数据与缩略图；原图下载在低优先后续阶段进行。
- 点击 thumbnail-ready 项，详情在原图 HTTP 完成前出现该项缩略图；原图请求提升到最高访问优先级。
- 浏览提升对应图片任务；一次后台任务不会因点击或多处引用重复下载。
- 原图就绪前宫格持续使用缩略图，原图完成不会触发宫格读取整张原图。
- 快速切换 A/B，A 的晚完成结果不能替换 B。
- 原图失败、网络中断或进程重启后仍可使用缩略图，并继续待办。
- 内容编辑时两角色一起更新；错误 generation/跨 namespace 绑定拒绝。
- 记录/缩略图完成和原图完成的进度分别真实显示。

服务端覆盖角色、绑定、摘要和资源请求；PhotoViewer 后续使用实际浏览/点击路径验证界面与调度，不用直接设置 UI/数据库终态绕过输入。
