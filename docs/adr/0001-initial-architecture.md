# ADR 0001：Rust 单进程、元数据版本索引与独立资源服务

日期：2026-10-13。状态：设计阶段采用；实现尚未开始。

## 背景

需要无变化轮询不重新哈希正文，并支持初次一致清单、可靠增量和资源恢复。用户指定 Rust、自主服务端和 CloudKit 风格兼容；先建立设计，再开发。

## 决策

- 使用 Rust + Tokio + Axum，独立仓库。
- 首版 SQLite WAL、单写入所有者、不可变资源文件；网络和资源 I/O 不进入数据库事务。
- 记录身份、revision、digest、sync token 与 query marker 分离。
- 保留历史版本，通过固定水位和 keyset 分页实现一致清单。
- 上传稳定资源后提交记录；通过发布意图恢复跨数据库/文件系统窗口。
- 首版不裁剪历史、不做资源 GC、不引入多实例。
- CloudKit 兼容为明确子集；不模拟 Apple 身份与加密。
- 照片上传原图与缩略图；下行按元数据、缩略图、原图分层，访问可提高队列优先级。

## 代价

历史版本和未引用资源会增长，需监测容量；首版不提供多实例高可用。保留历史使快照和下载恢复更简单，但不能无限期忽略后续裁剪与 GC 设计。

SQLite 和 FoundationDB 的选择需要根据真实规模与资源验证。Record Layer 的版本索引思想可借鉴，不要求部署整套分布式组件。

## 重新评估条件

实际测量发现单写入队列、历史存储或恢复时间超过部署目标；需要多账户、多实例、高可用或对象存储。变更必须新增 ADR，并保持 API 和客户端恢复语义。
