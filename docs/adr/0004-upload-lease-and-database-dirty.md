# ADR 0004：持锁检查最新进度、阶段上行与数据库 dirty

日期：2026-10-13。状态：采用设计，待 M3/M4/C1 实现。此决策以用户最新规则补充 ADR 0001–0003；不修改照片双资源完整后显示的决定。

## 决策

- 同 namespace 同时一个设备持有有效上行租约，下行仍多端并发。
- 正常下行后获取租约；失败直接跳过本轮上行。持锁核对云端最新 token 与本地 appliedToken；未追平则持锁重新下行并保活，再检查。
- token 比较由服务端验证范围/种类/代际/完整水位后的语义比较完成，不做客户端原始字符串比较；本地还确认 inbox/资源/冲突协调完成。
- 上行固定删除 → 修改 → 新增。元数据修改不传文件，内容修改上传变化资源并原子绑定；保留 revision 条件和照片配对图校验。
- 到期/失效令当前轮不可逆终止，取消当前和后续所有未完成上行任务并逐项报错；已有效确认的成功项不回滚，迟到回调不能清 dirty。
- fencing counter 持久单调，旧持有者在最终写入时被拒绝；正常服务器重启失效租约，不重置正常元数据同步 generation。
- dirty 直接使用本地既有同步记录的字段。无独立 dirty 文件/台账/持久队列；执行视图从数据库派生，只有有效成功确认回调更新对应 dirty/上行确认基线字段，新本地变更保持。
- ingestToken 与 appliedToken 各自保存在既有同步进度字段中；已可靠接收 token 不能证明本地资源/冲突已经结算。

## 代价与边界

这会增加原生租约/进度/阶段接口与变更请求头，启用后所有兼容变更入口统一受控；M2 当前没有这些行为。获取失败不阻塞下行，但本轮 dirty 仍有未完成义务，不能标记全库已同步。

锁内重新下行期间其他设备不能上行，须持续保活；可能延长占锁时间，用户选择了这一同步语义。大文件正文时限和失败恢复仍独立，首版不宣称支持上传断点续传。

响应丢失/失锁时不能承诺服务端未提交；需要无锁的提交事实读取与下一轮协调。并发的本地编辑必须有本地版本/轮次防护，避免旧成功回调清除新 dirty。内部下载/发布不应重新产生用户 dirty。

照片角色完整性、原图/缩略图均就绪再显示、上传范围/删除抑制和服务器正文零重复哈希约束继续有效。
